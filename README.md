# IT-ВЕЧЕ

Веб-портал для анонимного голосования руководителей на очной планёрке. Большой экран показывает презентационный режим 16:9, участники голосуют со смартфонов по QR-коду. Регистрация, имя и email не нужны.

- **Участник:** `/s/<код-сессии>` (сюда ведёт QR). Корень `/` перенаправляет на текущую сессию.
- **Экран зала:** `/hall/<код-сессии>`.
- **Организатор:** `/admin`, памятка: `/admin/guide`.

## Быстрый старт (локально)

Нужен Node.js 20+ (проверено на 22).

```bash
npm install
npm run dev          # сервер :3000 + интерфейс :5173 с горячей перезагрузкой
# открыть http://localhost:5173/admin, пароль разработки: veche-dev-password
```

Production-сборка одним процессом:

```bash
npm run build
ADMIN_PASSWORD='сильный-пароль' APP_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))") \
NODE_ENV=production PUBLIC_BASE_URL=http://localhost:3000 npm start
# http://localhost:3000/admin
```

## Проверки

```bash
npm run check        # ESLint + TypeScript + автотесты (правила, API, безопасность)
TEST_DATABASE_URL=postgresql://... npm test   # те же API-тесты дополнительно на PostgreSQL
npm run build && npm run e2e   # сквозной сценарий в Chromium (телефон + зал + админ) и скриншоты в screenshots/
```

## Архитектура и почему такой стек

| Слой | Технологии |
|---|---|
| Интерфейс | React 18 + TypeScript + Tailwind CSS + Framer Motion + Lucide, сборка Vite |
| Сервер | Node.js + Express, один процесс отдаёт API, живые обновления и статику |
| База | SQLite (файл, по умолчанию) или PostgreSQL через `DATABASE_URL` (например, бесплатный Neon). SQL-миграции для обеих — в `server/src/migrations/{sqlite,postgres}` |
| Живые обновления | Server-Sent Events, при сбое автоматический переход на опрос каждые 3 с |

В ТЗ предпочтительным назван Supabase, но допускается эквивалентная архитектура. Я выбрала один Node-процесс с SQLite или PostgreSQL на выбор, потому что:

- **Запуск одной командой** и без внешних аккаунтов: локально всё работает на SQLite-файле. Для бесплатного хостинга база выносится в PostgreSQL (Neon).
- **Те же гарантии, что дают RLS-политики.** Браузер никогда не обращается к базе напрямую, а сервер отдаёт только агрегаты, и только после того, как организатор опубликовал результаты. Ограничения дополнительно продублированы на уровне БД: уникальность `(round_id, anonymous_voter_key)`, триггеры «голос только в открытый тур», «только допустимый вариант», «синтетические голоса только в демо», «голоса неизменяемы».
- **Нагрузки хватает с большим запасом.** 40 участников — это десятки запросов. Гонки (двойная отправка, голос в момент закрытия тура) закрыты транзакциями, блокировкой строки тура и уникальными ограничениями. Это проверено тестами на обеих базах.

Подробности: [docs/architecture.md](docs/architecture.md).

## Публикация (деплой)

Порталу нужен **публичный HTTPS-адрес** (на него ведёт QR-код) и **надёжное хранилище голосов**.

### Бесплатно: Render Free + Neon (рекомендуется)

1. **Neon** ([neon.tech](https://neon.tech)): создайте проект (регион Frankfurt) и скопируйте *Connection string*. Если в конце строки есть `&channel_binding=require`, удалите этот фрагмент.
2. **Render** ([render.com](https://render.com)): нажмите **New → Blueprint** и выберите этот репозиторий. Render прочитает `render.yaml` и попросит ввести:
   - `ADMIN_PASSWORD` — пароль организатора (не короче 10 символов);
   - `DATABASE_URL` — строку подключения из Neon.

   `APP_SECRET` сгенерируется автоматически.
3. Через 3–5 минут портал будет доступен по адресу `https://it-veche-xxxx.onrender.com`.

Бесплатный сервер Render засыпает после 15 минут без запросов, и первое открытие после этого занимает до минуты. **Откройте экран зала за 2–3 минуты до начала**: дальше он сам держит соединение. Голоса хранятся в Neon и при засыпании не теряются.

### Платно: один контейнер с диском (Railway, Render Starter, Fly.io, VPS)

```bash
docker build -t it-veche .
docker run -d -p 3000:3000 -v veche-data:/data \
  -e ADMIN_PASSWORD='...' -e APP_SECRET='...' -e PUBLIC_BASE_URL='https://veche.example.com' it-veche
```

Без `DATABASE_URL` используется SQLite-файл `/data/veche.db`, поэтому подключите постоянный диск к `/data`. Для SSE за nginx отключите буферизацию: `proxy_buffering off`.

Запускайте **один экземпляр** сервера: живые обновления и ограничение частоты работают в памяти процесса.

## Честные ограничения

- **Один голос на человека не гарантирован без идентификации.** В открытом режиме один голос приходится на браузер (ключ хранится в `localStorage`). Участник может проголосовать повторно из другого браузера, другого устройства или режима «Инкогнито». Для строгого режима включите **одноразовые коды** при создании сессии: они раздаются на карточках и не привязаны к именам.
- **Очистка данных браузера** между турами не даст проголосовать дважды в одном туре, только если используются коды.
- **Проверено** автотестами и сквозным сценарием в Chromium с эмуляцией iPhone 13 и экрана 1920×1080. На реальных iPhone/Android и в Safari прогон не выполнялся. Перед встречей пройдите [чек-лист на смартфоне](docs/manual-test-checklist.md).
- **Docker-образ не собирался** в среде разработки (нет Docker-демона). Его соберёт хостинг при первом деплое.
- **Масштабирование.** Состояние живых обновлений хранится в памяти, поэтому несколько экземпляров сервера потребуют общей шины (Redis/Postgres LISTEN). Для 10–40 участников это не нужно.
